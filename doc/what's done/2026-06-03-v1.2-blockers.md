## BLK-1 🔴 · T6 readiness 读错 org（跨租户泄露 + 功能 bug）

**根因（已核实）:** [agent/page.tsx](../../apps/console/app/admin/agent/page.tsx) 的 T6 readiness 调用 `fetch('/api/livechat/config')` **未带 `orgId`**。该路由 [config/route.ts:22](../../apps/console/app/api/livechat/config/route.ts#L22) 解析为 `searchParams.get('orgId') ?? 'default'`——**不从 session 取**，且在 middleware 保护范围外（widget/webhook 面向，带 CORS）。

**后果:** 非 `default` org 的 `readiness.livechat` 永远读到 `default` org 的配置 → 恒错；任何 org 都能借此探知 `default` 是否配了 livechat → 跨租户信息泄露。

**修法（二选一，推荐第 2 个）:**
1. **最小修**：T6 先取 session orgId（参考 livechat 页 [livechat/page.tsx:176-177](../../apps/console/app/admin/channels/livechat/page.tsx#L176) 的 `fetch('/api/auth/session')` 取 orgId），再 `fetch('/api/livechat/config?orgId=${orgId}')`。
2. **更稳（推荐）**：readiness 的 livechat 状态改走 session 域内来源——要么新增/复用一个 `/api/admin/*` 下、用 `getActiveOrgId()` 解析的只读端点返回 livechat enabled 状态，要么让 `/api/livechat/config` 在**有合法 session 时优先用 session orgId**（见 BLK-1b）。

**BLK-1b（连带加固，建议同批做）:** 给 `/api/livechat/config` GET 与 `/api/livechat/groups` 增加"有 session 则用 session orgId、忽略客户端 param"的逻辑（保留无 session 的 widget 路径）。这同时修复 GENERIC_HANDOFF §4 Gotcha #7 记录的隐患。**注意:** 这是鉴权相关改动，必须配 BLK-2 的守卫测试。

**验收:** 切到非 default org，readiness.livechat 反映的是**该 org** 的真实配置；无法读到其它 org 的 livechat 状态；截图（default + 一个非 default org 各一）。

## BLK-2 🔴 · T6 跨 org 守卫测试缺失（铁律红线）

**问题:** T6 任务明确要求 e2e red→green 守卫测试，证明 readiness 聚合**不跨 org**。当前未写（`apps/console/**/__tests__` 无新增）。这正是能拦住 BLK-1 的测试。

**做法:** 写驱动真实入口的 e2e 测试（非 mock/seam）：
- 建两个 org（如 `default` + `orgB`），各自不同的 livechat config / api-keys。
- 以 `orgB` 的 session 触发 readiness 数据获取路径，断言**只**返回 `orgB` 的数据，**绝不**含 `default` 的 livechat/key 状态。
- 先复现 BLK-1（red），修复后转 green。

**验收:** 贴 red→green 测试输出；测试覆盖"非 default org 不会读到 default org 配置"。

## BLK-3 🟡 · zh 字典缺 3 个 key + 反模式 key

**根因（已核实）:** `lib/i18n/dictionaries.ts` 中 `en` 有 1091 key、`zh` 仅 1088。`zh` 缺：
- `agent.invariantCheck`
- `agent.invariantCheckHint`
- `agent.invariantCheckHintZh` ← 本身是反模式：在 `en` 块里塞 `Zh` 后缀 key，而非用 `zh` 字典。

**做法:** 在 `zh` 补齐 `agent.invariantCheck` / `agent.invariantCheckHint` 的中文翻译；删除 `agent.invariantCheckHintZh` 这个反模式 key，调用处改用标准 `t('agent.invariantCheckHint')`（中文走 zh 字典）。校验 en/zh key 数对称。

**验收:** en/zh key 数一致；切中文时 invariantCheck 相关文案为中文、无 key 名裸露；`tsc` 通过。
